# План реализации VPS.md

## Контекст

Пользователь хочет пройти полный путь: от выбора VPS до готового подключения VLESS + Reality через sing-box. VPS ещё не куплен, страна не выбрана. Результат должен быть в виде Markdown-файлов в этой папке.

## Что делает этот план

Создать шесть связанных Markdown-документов, которые превращают `VPS.md` из статичного руководства в набор рабочих артефактов: заполняемые шаблоны, runbook'и, проверки и промпты. Реальные действия с оплатой, SSH и генерацией секретов остаются за пользователем, но каждый шаг будет детально подготовлен.

## Артефакты

| Файл | Назначение |
|---|---|
| `01-requirements.md` | Выбор страны под карту, платёж, бюджет, количество устройств; заполняемый шаблон входных данных; Промпт 1 для сравнения VPS. |
| `02-purchase-checklist.md` | Чек-лист перед покупкой, генерация SSH-ключа, сохранение критичных полей. |
| `03-server-setup.md` | Server setup runbook: preflight, safety, SSH hardening, firewall, sing-box, Reality handshake, secrets, server config, service activation. |
| `04-client-setup.md` | Шаблон клиентского JSON, инструкция импорта в SFM, совместимость SFM 1.13.14. |
| `05-verification.md` | End-to-end verification runbook, Промпт 3, PASS/FAIL таблица, sanitized-отчёт. |
| `06-troubleshooting.md` | Таблица проблем/решений, rollback-процедуры, управление секретами. |
| `README.md` | Мастер-индекс: quick-start, карточки этапов, зависимости, ссылки. |

## Принципы

- На VPS работает только sing-box и системные компоненты.
- Claude Code, Codex, Node.js, Git-проекты, токены и файлы авторизации остаются локально.
- Секреты (UUID, Reality keys, short_id, profile JSON) не публикуются и не показываются в открытом виде.
- Никакого `insecure: true`.
- Каждая фаза server setup имеет rollback и PASS/FAIL проверку.

## Ограничения

- Я не могу купить VPS или провести оплату.
- Я не могу подключиться к реальному серверу без предоставленных SSH-доступа и IP.
- Я не могу генерировать реальные секреты и выводить их в чат.
- Поэтому «реализация» = создание полного набора рабочих артефактов, которые пользователь выполняет сам или с помощью AI-ассистента на своём устройстве.

## Порядок работы

1. Создать `01-requirements.md`.
2. Создать `02-purchase-checklist.md`.
3. Создать `03-server-setup.md`.
4. Создать `04-client-setup.md`.
5. Создать `05-verification.md`.
6. Создать `06-troubleshooting.md`.
7. Создать `README.md`.
8. Проверить внутренние ссылки и целостность.

## Критерий готовности

Все семь файлов созданы, шаблоны содержат плейсхолдеры, runbook'и содержат команды и точки проверки, README даёт понятный quick-start.
